# Zombi3 Trip — сайт отеля с PostgreSQL и Docker

Русскоязычное многостраничное приложение: HTML/CSS/JavaScript + Node.js/Express API + PostgreSQL.

## Что реализовано
- Регистрация и вход через сервер; пароли хешируются `bcryptjs` (12 раундов).
- JWT в HttpOnly cookie; пароль и токен не хранятся в localStorage.
- PostgreSQL хранит пользователей и заявки на бронирование.
- Сервер проверяет поля, даты, число гостей, тип номера и пересчитывает стоимость сам.
- Личный кабинет загружает реальные заявки авторизованного пользователя.
- Docker Compose запускает веб-приложение и PostgreSQL; база сохраняется в Docker volume.
- Избранные номера пока хранятся локально в браузере.
- Платёжная система и подтверждение реальной доступности номеров не подключены: заявка имеет статус `pending`.

## Запуск через Docker

1. Установите Docker Desktop и запустите его.
2. В папке проекта скопируйте `.env.example` в `.env`.
   - Windows PowerShell: `Copy-Item .env.example .env`
   - macOS/Linux: `cp .env.example .env`
3. Откройте `.env` и задайте два уникальных длинных секрета: `POSTGRES_PASSWORD` и `JWT_SECRET` (не менее 32 символов для JWT).
4. В папке проекта выполните:

   ```bash
   docker compose up --build -d
   ```

5. Откройте `http://localhost:3000`.
6. Проверка API и подключения к БД: `http://localhost:3000/api/health`.

## Полезные команды

```bash
docker compose ps
docker compose logs -f web
docker compose logs -f db
docker compose down
```

`docker compose down` не удаляет данные базы. Чтобы удалить и базу данных целиком, используйте `docker compose down -v` — это необратимо удалит сохранённые данные.

## Важно для продакшена
Перед публичным развёртыванием настройте HTTPS и `COOKIE_SECURE=true`, ограничение частоты запросов, резервное копирование, секреты через менеджер секретов и мониторинг. Сейчас `COOKIE_SECURE=false` задан для удобного локального запуска. Нет платежей, email-подтверждения и проверки фактической доступности номеров.
